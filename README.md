# 求职助手 · Tampermonkey 脚本集

一套跑在浏览器里的求职自动化脚本，覆盖 **智联招聘**、**BOSS 直聘**、**猎聘** 三个平台。
核心能力：批量投递 / 打招呼、自动切换城市续跑、基于大模型的 AI 自动回复。

---

## 脚本一览

| 平台 | 文件 | 版本 | 能力 | 说明 |
|---|---|---|---|---|
| 智联招聘 | `ZhaoPin_helper.js` | 1.3.0.0 | 批量投递 / 打招呼、城市自动切换、IM 页 AI 自动回复 | 功能最完整，主力脚本 |
| BOSS 直聘 | `Boss_helper.js` | 2.2.0.0 | 批量沟通、AI 智能回复 | 上游版本的本地改进版 |
| 猎聘 | `Liepin_helper.user.js` | 0.4.0 | 排除猎头、依次自动打招呼 | 最小化实现，筛选沿用页面自带 |

三个脚本彼此独立，装任意一个都能单独工作。

---

## 安装

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox 均可）
2. 新建脚本 → 把对应 `.js` 文件的**全部内容**粘进去 → 保存
3. 打开目标站点，右下角出现控制面板即为生效

> 首次安装时 Tampermonkey 会申请「访问所有网站」权限，**必须点允许**，
> 否则 AI 接口的请求会被拦掉（详见 [AI 配置](#ai-配置)）。
> 若使用过程中还弹出域名授权确认，见 [授权弹窗](#关于授权弹窗)。

## 智联助手

### 职位列表页：批量投递

打开 `https://www.zhaopin.com/jobs?...`，面板上：

| 项目 | 说明 |
|---|---|
| 职位名包含 | 逗号分隔的关键词，命中的岗位才处理 |
| 工作地包含 | 目标城市；填了会**自动切换城市并续跑**，不用手动翻页 |
| 启动海投 | 开始；再点一次停止 |

**投递方式**在面板 `⚙` → 高级设置 → 投递方式：

- `立即投递简历` —— 直接投简历（默认）
- `先聊聊` —— 先打招呼

两者的区别只在于点详情面板上的哪个按钮，其余流程一致。

### 消息页：AI 自动回复

智联的消息中心不在 `www`，而在 **`https://i.zhaopin.com/im/`**。
脚本对这个域名同样生效，打开后：

1. 面板提示「我将自动发送简历」，按钮变为 **开始智能聊天**（列表页才叫「启动海投」）
2. 点击后自动点开当前会话，并建立新消息监听
3. HR 发来新消息 → 调 AI 生成回复 → 自动发送

配置只在**任意一个页面**设一次即可。脚本用 Tampermonkey 的跨页存储，
`www.zhaopin.com` 和 `i.zhaopin.com` 之间配置是互通的（这两个域名的 localStorage 本身不共享）。

招呼语由智联在职位页点「先聊聊」时**自动发出**，脚本不会重复发一遍。

## BOSS 直聘助手

打开 `https://www.zhipin.com/web/...`，用法与智联职位页一致：筛选 → 启动 → 自动沟通。
AI 回复逻辑与智联共用同一套实现。

## 猎聘助手

打开 `https://www.liepin.com/zhaopin/...`，面板上点开始：

```
扫描卡片 → 排除猎头 → hover 出「聊一聊」→ 点击 → 等聊天窗 → 关闭 → 下一个
```

- **排除猎头**是四层判定：推广标签、公司名关键词、招聘者信息、职位名关键词
- **筛选不自己做**，沿用你在页面上设好的筛选条件
- 猎聘的招呼语同样是系统自动发的，脚本只负责点「聊一聊」
- 单次会话上限 20 个，间隔 3.5 秒

## AI 配置

三个脚本的 AI 配置面板一致，入口：面板 `⚙` → AI 配置。

| 字段 | 说明 |
|---|---|
| API Key | 你的密钥 |
| API URL | 兼容 OpenAI 的 `/chat/completions` 地址 |
| 模型 | 填服务商给的模型 id |
| 角色设定 | system prompt，留空用默认 |

面板提供 硅基流动 / 火山引擎 / OpenAI / DeepSeek / 自定义 五种预设，
点一下自动填好地址，**不影响**你手动改成任何第三方。

### 自建网关 / NAS

如果用的是自建的 OpenAI 兼容网关（比如 NAS 上的转发服务）：

- API URL **可以只填到主机和端口**，例如 `http://192.168.31.136:7863`，
  脚本会自动补上 `/v1/chat/completions`，不用手填完整路径
- 模型 id 填网关 `/v1/models` 里查到的真实值

脚本同时声明了常用域名和 `@connect *`：常见接口直连不弹窗，
其余第三方接口首次请求时会弹一次确认，见下节。

### 关于授权弹窗

Tampermonkey 对 `GM_xmlhttpRequest` 有两层控制，缺一个都会弹确认框：

| 声明方式 | 效果 |
|---|---|
| 脚本里 `@connect 具体域名` | 该域名**静默放行**，不弹窗 |
| 脚本里 `@connect *` | 不消除弹窗，但弹窗上会多出「始终允许所有域」按钮 |
| 脚本设置 → XHR 安全 → 用户域白名单 加 `*` | 全部请求静默放行 |

所以本项目的做法是**两者都写**：常用域名（含自建网关地址）显式声明以免打扰，
末尾追加 `@connect *` 作为任意第三方的兜底。

**彻底消除弹窗，二选一**：

1. 弹窗出现时点 **「始终允许所有域」**（Always allow all domains）—— 一次生效，之后不再问
2. 打开 脚本设置 → XHR 安全 → 用户域白名单，手动添加 `*`

如果换了网关地址（比如 NAS 换 IP），把脚本里的 `@connect` 那行同步改掉即可，
不改也不影响使用，只是会多弹一次确认。

### 常见问题

| 现象 | 原因 |
|---|---|
| 「网络请求失败」 | 安装时没点「允许访问所有网站」，或网关没起来 |
| 「响应解析失败: Unexpected token <」 | 地址填错，拿到了 HTML 页面而不是接口 |
| 「请求超时(10秒)」 | 地址不通，或被思考型模型拖慢 |
| 「未配置AI API」 | Key / URL / 模型 三项有空 |

排错顺序：**先测连接**（面板里有按钮），再查 Key 和 URL。
网关不带 Key 时通常返回 401，这能证明网关本身是活的。

## 注意

- 自动化投递存在平台风控风险，建议控制频率、不要长时间无人值守
- `@connect *` 意味着脚本可向任意域名发请求，请确保脚本来源可信
- 本项目仅供个人学习使用，请遵守各平台的使用条款
